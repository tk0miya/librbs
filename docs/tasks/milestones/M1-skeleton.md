# M1: Skeleton

## Goal

Get to a state where `require "librbs"` succeeds, the native extension loads,
and `Librbs::Native.hello` is callable. Patches are wired up but no-op (i.e.
behavior is identical to pure RBS).

The purpose is to provision the foundation that subsequent milestones build
on, including CI.

## Prerequisites

- Read [../README.md](../README.md) and [../design.md](../design.md) before
  starting.
- The repository currently contains nothing other than `vendor/rbs/`.
- Bundler 2.5+ (for `bundle gem --ext=rust`).

## Approach

Bootstrap the gem skeleton with **`bundle gem --ext=rust librbs`** in a
scratch directory, then move the generated files into the repository root and
modify them. This ensures conventional layout (gemspec, Rakefile,
`ext/librbs/extconf.rb`, `crates/librbs/`, `Gemfile`, license/test scaffold,
etc.) and the standard rb-sys / rake-compiler glue.

We **do not copy** `vendor/rbs/rust/ruby-rbs` or `ruby-rbs-sys` into our
crate tree. They are referenced via Cargo path dependencies (see step 2).

## Final layout (after editing the generated scaffold)

```
librbs/
├── Cargo.toml                          # workspace root; depends on vendor/rbs/rust crates by path
├── Cargo.lock
├── crates/
│   ├── librbs/                         # generated by `bundle gem --ext=rust`; rename or split as below
│   │   ├── Cargo.toml                  # → repurpose as crates/librbs-ruby
│   │   ├── extconf.rb -> ../../ext/... # depends on what `bundle gem` emits; reorganize as needed
│   │   └── src/lib.rs
│   ├── librbs-core/                    # new: discovery / env / resolver
│   └── librbs-ruby/                    # the magnus extension (renamed from generated `librbs/`)
├── ext/
│   └── librbs/
│       └── extconf.rb                  # generated; tweak only if necessary
├── lib/
│   ├── librbs.rb                       # generated; rewrite for our require chain
│   └── librbs/
│       ├── version.rb                  # generated
│       └── patches.rb                  # new (no-op in M1)
├── sig/                                # generated empty; leave as-is
├── spec/                               # generated rspec scaffold
├── Gemfile                             # generated; ensure rspec is in :development
├── librbs.gemspec                      # generated; adjust dependencies and files glob
├── Rakefile                            # generated
└── .github/workflows/ci.yml            # new (Bundler may emit a stub; replace)
```

The generator typically produces a single `crates/librbs/` for the extension.
We split that into two crates: **`librbs-core` (Ruby-independent)** and
**`librbs-ruby` (the magnus cdylib)**. The generator's
`crates/librbs/Cargo.toml` becomes the basis for `crates/librbs-ruby`.

## Tasks

### 1. Generate the skeleton

In a clean workspace:

```bash
bundle gem --ext=rust --test=rspec --linter=none --no-coc --no-mit librbs
```

(Adjust `--coc`/`--mit` to your preference; pick whatever the project policy
becomes. The above is one example.)

Move the generated files into the repository root, on top of the existing
`vendor/rbs/` directory. Resolve any conflicts on a per-file basis.

Commit the unmodified generated scaffold in one commit so the diff for the
next steps is clean.

### 2. Workspace and path dependencies on vendor crates

Edit `/Cargo.toml` so it becomes a workspace root with our crates as members
and `vendor/` excluded:

```toml
[workspace]
resolver = "3"
members = [
    "crates/librbs-core",
    "crates/librbs-ruby",
]
exclude = ["vendor"]   # avoid picking up vendor/rbs/rust/Cargo.toml's nested workspace
```

The vendor crates (`vendor/rbs/rust/ruby-rbs`, `vendor/rbs/rust/ruby-rbs-sys`)
remain in their own workspace under `vendor/rbs/rust/`. We depend on them as
path dependencies from our crates:

```toml
# crates/librbs-core/Cargo.toml
[dependencies]
ruby-rbs = { path = "../../vendor/rbs/rust/ruby-rbs" }
```

After setting this up, run `cargo build --workspace` from the repo root and
ensure it succeeds.

### 3. Split the generated extension crate

Rename `crates/librbs/` to `crates/librbs-ruby/` and create
`crates/librbs-core/` from scratch.

```toml
# crates/librbs-core/Cargo.toml
[package]
name = "librbs-core"
version = "0.0.0"
edition = "2024"

[dependencies]
ruby-rbs = { path = "../../vendor/rbs/rust/ruby-rbs" }
```

```rust
// crates/librbs-core/src/lib.rs
pub fn version() -> &'static str {
    env!("CARGO_PKG_VERSION")
}
```

```toml
# crates/librbs-ruby/Cargo.toml  (modified from the generated file)
[package]
name = "librbs-ruby"
version = "0.0.0"
edition = "2024"

[lib]
crate-type = ["cdylib"]

[dependencies]
magnus = "0.7"
librbs-core = { path = "../librbs-core" }
```

```rust
// crates/librbs-ruby/src/lib.rs
use magnus::{function, Error, Ruby};

fn hello() -> &'static str {
    "librbs alive"
}

#[magnus::init]
fn init(ruby: &Ruby) -> Result<(), Error> {
    let module = ruby.define_module("Librbs")?.define_module("Native")?;
    module.define_singleton_method("hello", function!(hello, 0))?;
    Ok(())
}
```

### 4. Update `ext/librbs/extconf.rb` to point at the renamed crate

The generator emits an `extconf.rb` that calls `create_rust_makefile`. Update
the crate path so it points at `crates/librbs-ruby` (or whatever name you
chose). Reference: <https://github.com/oxidize-rb/rb-sys>

### 5. Update `lib/librbs.rb`

Replace the generated body with our require chain and fail-safe fallback:

```ruby
# lib/librbs.rb
require "rbs"
require "librbs/version"

begin
  require "librbs/librbs"   # the .so/.bundle produced by ext/
  require "librbs/patches"
rescue LoadError => e
  warn "[librbs] native extension failed to load: #{e.message}"
  warn "[librbs] falling back to pure RBS implementation"
end
```

```ruby
# lib/librbs/patches.rb (new file; empty in M1)
module Librbs
  module Patches
  end
end
```

### 6. Adjust `librbs.gemspec`

Edits to the generated gemspec:

- Set `s.required_ruby_version = ">= 3.2"`.
- `s.platform = Gem::Platform::RUBY`.
- Add runtime dependencies:
  - `s.add_dependency "rbs", "~> 4.0"`
  - `s.add_dependency "rb_sys", "~> 0.9"`
- Update `s.files` so it includes `lib/**/*`, `ext/**/*`, `crates/**/*`,
  `Cargo.*`, and excludes `vendor/rbs/test/**` etc. (the upstream test
  fixtures should not ship with the gem).
- Confirm `s.extensions = ["ext/librbs/extconf.rb"]`.

### 7. Adjust the `Gemfile`

Make sure the `:development` group has `rake`, `rake-compiler`, and `rspec`.
The generator typically already adds these.

### 8. Adjust the `Rakefile`

The generator gives you a Rakefile that registers `RbSys::ExtensionTask`.
Confirm `task default: %i[compile spec]` is set.

### 9. Add the CI workflow

Replace any generator-emitted stub at `.github/workflows/`:

```yaml
# .github/workflows/ci.yml
name: CI
on:
  push:
    branches: [main]
  pull_request:

jobs:
  rust-test:
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - run: cargo test --workspace

  rust-lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with: { components: "rustfmt, clippy" }
      - run: cargo fmt --check
      - run: cargo clippy --workspace -- -D warnings

  ruby-test:
    strategy:
      fail-fast: false
      matrix:
        ruby: ["3.2", "3.3", "3.4", "4.0"]
        os: [ubuntu-latest, macos-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: oxidize-rb/actions/setup-ruby-and-rust@v1
        with:
          ruby-version: ${{ matrix.ruby }}
          rustup-toolchain: stable
          bundler-cache: true
          cargo-cache: true
      - run: bundle exec rake compile
      - run: bundle exec rake spec
```

### 10. Sanity test

Replace or extend the generated rspec sample:

```ruby
# spec/librbs_spec.rb
RSpec.describe Librbs do
  it "loads native extension" do
    expect(Librbs::Native.hello).to eq("librbs alive")
  end
end
```

## Acceptance

M1 is complete when all of the following hold:

- [ ] `cargo build --workspace` succeeds
- [ ] `cargo test --workspace` succeeds
- [ ] `cargo fmt --check` and `cargo clippy --workspace -- -D warnings` pass
- [ ] `bundle install && bundle exec rake compile` succeeds locally on Linux
      or macOS
- [ ] `bundle exec rake spec` makes the `Librbs::Native.hello` test green
- [ ] `require "librbs"` does not raise `LoadError`; on native-load failure,
      it prints a warning and continues (verified manually)
- [ ] All CI jobs (`rust-test`, `rust-lint`, `ruby-test`) are green on the
      ubuntu / macos matrix

## Out of scope for this milestone

- Any logic beyond `Librbs::Native.hello` (M2 onward)
- Patch bodies (M3 onward)
- Compatibility tests (M3 onward)
- Benchmarks (after M3)
- Cross-gem distribution (just before release)

## Pitfalls and mitigation

### Conflicts with `vendor/rbs/`

`bundle gem` may emit files (e.g. `README.md`) that conflict with paths in
`vendor/rbs/`. Inspect each conflict and decide whether to keep the
generator's version, the vendor version, or merge.

### Nested workspace at `vendor/rbs/rust/Cargo.toml`

`vendor/rbs/rust/Cargo.toml` declares its own `[workspace]`. Keep our
workspace from picking it up by setting `exclude = ["vendor"]` in our root
`Cargo.toml`. The vendor crates remain buildable as path dependencies.

### magnus version

Target `magnus` 0.7.x. Verify before starting M1 that the chosen magnus
release supports Ruby 3.2 through 4.0 inclusive; bump the version constraint
if a newer line is required for Ruby 4.0 compatibility.
Reference samples: <https://github.com/matsadler/magnus/tree/main/examples>

### rb-sys extconf

The path passed to `create_rust_makefile` is a directory, not a crate name.
It is interpreted relative to the workspace root. The oxidize-rb template is
a useful reference:
<https://github.com/oxidize-rb/rb-sys-cargo-template>
